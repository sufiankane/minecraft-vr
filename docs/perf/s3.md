# S3 meshing performance and budget

Local measurements for the S3 `Cubeglass.Mesh` hot path (`GreedyMesher.Build`
plus `MeshData.Release`), against the ADR-0007 budget. These are a local
baseline record; the authoritative nightly numbers are CI artefacts (see
[`README.md`](README.md)).

- **Date:** 2026-10-02
- **Machine:** AMD Ryzen AI 9 365 w/ Radeon 880M (10 physical / 20 logical
  cores, 2.00 GHz), 23 GiB RAM, Windows 11 10.0.26200.9550 (25H2)
- **Toolchain:** .NET SDK 10.0.401 (runtime 10.0.12, X64 RyuJIT), Release,
  BenchmarkDotNet 0.15.8

## Budget harness (`p95` mode)

The ADR-0007 budget harness is the `p95` argument of the Mesh benchmark
project: after 100 warm-up builds it runs 2,000 build/release cycles per chunk
shape and prints p50/p95/p99 in milliseconds. Add `--budget-ms <n>` to make the
harness exit non-zero when any shape's p95 exceeds `n`. The nightly lane
enforces the shared-runner budget of 8 ms; 2.0 ms remains the release/local
budget asserted here.

Command (from `dotnet/`):

```powershell
dotnet run --configuration Release --project benchmarks/Mesh.Benchmarks/Mesh.Benchmarks.csproj -- p95 --budget-ms 2
```

Result (2026-10-02, commit `0741f9c` plus the Task 4 working tree):

| Shape | Quads | p50 (ms) | p95 (ms) | p99 (ms) | Budget p95 |
| --- | ---: | ---: | ---: | ---: | --- |
| `GreedySolidChunk` (full 16³ stone) | 6 | 0.279 | **0.442** | 0.486 | ≤ 2.0 ms — PASS |
| `GreedyTerrainChunk` (seed 42, origin) | 240 | 0.245 | **0.405** | 0.440 | ≤ 2.0 ms — PASS |
| `GreedyCheckerboardChunk` (2×2×2 stone, R22 worst case) | 5,568 | 0.990 | **1.363** | 1.585 | recorded, not the ADR case |

ADR-0007's budget is p95 ≤ 2.0 ms per full 16³ chunk for a solid or terrain
chunk built with `GreedyMesher`; both cases clear it with more than 4×
headroom. The checkerboard is the pathological merge case (per-cell AO keeps
~5,568 quads separate, matching the R22 estimate) and still clears the budget.
