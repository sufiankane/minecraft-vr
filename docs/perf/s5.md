# S5 glasses performance, allocation and probe gates

Local measurements for the S5 glasses adapters and the wait-free pose read
path. These are a local baseline record, not a regression gate: the
authoritative nightly numbers are CI artefacts (see [`README.md`](README.md)).

- **Date:** 2026-10-02
- **Machine:** AMD Ryzen AI 9 365 (20 logical CPUs, 2.0 GHz base), 23 GiB RAM,
  Windows 11 Enterprise 10.0.26200
- **Toolchain:** MSVC 19.51.36256 (VS 18.9 BuildTools), CMake 4.3.1-msvc1,
  Ninja 1.13.2, Google Benchmark 1.9.5, CMake/Ninja Release (`benchmarks`
  preset)

## Wait-free read benchmark

`BM_TryGetLatest` drives a `VitureHeadPoseSource` over the programmable test
fake, waits for one published sample, stops the source (so the polling thread
cannot perturb the measurement) and then times the reader-side
`TryGetLatest(sample, predict=0)`. The glasses benchmark joins the existing
`cg_core_math_benchmarks` target.

Command (from `cpp/`, Release):

```powershell
cmake --preset benchmarks
cmake --build --preset benchmarks
.\build\benchmarks\bin\cg_core_math_benchmarks.exe --benchmark_min_time=0.2s
```

| Benchmark | Operation | Time (ns/op) | CPU (ns/op) |
| --- | --- | ---: | ---: |
| `BM_TryGetLatest` | `VitureHeadPoseSource::TryGetLatest(out, 0)` after Stop | 6.08 | 6.28 |

Repetition run for the distribution (10 repetitions, aggregates only,
`--benchmark_filter=BM_TryGetLatest --benchmark_min_time=0.2s`):

| Statistic | Time (ns/op) | CPU (ns/op) |
| --- | ---: | ---: |
| mean | 6.24 | 6.31 |
| median (p50) | 6.19 | 6.28 |
| stddev | 0.121 | 0.110 |
| cv | 1.94 % | 1.75 % |

The read is wait-free: the seqlock copy plus the predict-0 checks, with no
locks, allocation or blocking (proved separately by the allocation gate
below). Numbers include the `DoNotOptimize` sink and are not comparable across
machines; no absolute threshold is applied.

## Allocation gate

`cpp/tests/glasses/allocation_tests.cpp` overrides the replaceable global
allocation functions in its translation unit and snapshots the counter around
two warmed-up 1M-iteration loops: `PoseSlot::TryRead` on a published slot and
`VitureHeadPoseSource::TryGetLatest` over the test fake (the source is stopped
before the measured region, so no producer thread can allocate concurrently).
The counter was proven with a deliberate `delete new int(1);` probe inside each
measured loop first:

| Run | Result |
| --- | --- |
| Probe present (RED) | both tests failed, each reporting `1000000` allocations over 1000000 iterations |
| Probe removed (GREEN) | both tests passed; delta `0` for both read paths |

Command:

```powershell
.\build\windows-msvc\tests\glasses\cg_glasses_tests.exe --gtest_filter=AllocationTest.*
```

## Pose probe smoke run

`cg-pose-probe` is the S5 HIL instrument (`cpp/tools/pose_probe/main.cpp`). The
fake source is wall-paced by a steady clock at `--rate` (the probe raises the
Windows timer to 1 ms for the run), the replay source keeps the dataset's own
intervals when `--rate` is absent, and the optional CSV uses the S5 replay
header `host_time_ns,sdk_time_s,px,py,pz,qw,qx,qy,qz,status`. Because
`IHeadPoseSource` exposes only the mapped host time, `sdk_time_s` is
host-derived, not the raw SDK stamp (documented in `--help` and the tool's
header comment); `ReplayHeadPoseSource` parses and validates the column but
does not publish it.

Fake smoke, Release (`--seconds 2 --out` a scratch CSV):

```powershell
.\build\benchmarks\bin\cg-pose-probe.exe --source fake --seconds 2 --out $env:TEMP\cg-pose-probe-smoke.csv
```
