# S8 performance record — newest-wins frame slot (Task 2)

- **Date:** 2026-10-07
- **Machine:** owner's dev laptop (AMD Ryzen AI 9 HX 370, 20 logical CPUs, RTX
  5070 Laptop GPU), Windows 11.
- **Command:**
  `cg_core_math_benchmarks --benchmark_filter=BM_Slot --benchmark_min_time=2s`
- **Payload:** 640×480 per stream, four streams (f0 left/right, f1
  left/right) = 1.23 MB copied per frame.

| Benchmark | Time | Iterations | Counters |
|---|---|---|---|
| `BM_SlotPublishCallbackCopy` (publish only, static buffers) | **19.3 µs** | 68,923 | every frame overwritten (stalled consumer) |
| `BM_SlotPublishEndToEnd` (fake source fill + publish) | 309 µs | 5,271 | every frame overwritten |

Interpretation:

- The producer path copies 1.23 MB and returns in **~19 µs**, far inside the
  dossier 3.3 callback budget (the callback runs on the SDK thread and must
  return quickly). At a 60 Hz camera rate the copy is ~0.1 % of the period;
  with the writer stalled the slot simply overwrites, which the counters show.
- The end-to-end number is dominated by the fake's byte-wise pattern fill
  (~290 µs of helper-only work) and is recorded for contrast only; the real
  vendor callback hands us pointers, so the publish-only number is the one
  that bounds the SDK thread.
- The consumer's seqlock retry was never triggered in the single-threaded
  suites; the concurrent suite (`ConcurrentProducerAndConsumerNeverTear`,
  20,000 frames) keeps `TornRetries` visible if scheduling ever forces one.
