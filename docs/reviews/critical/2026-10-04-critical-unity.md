## Important findings

### I-1 — Bridge pose selection is single-shot: permanent silent fallback with `Stable` tracking

- **Files/lines:**
  - `unity/Cubeglass/Packages/com.cubeglass.rendering/Runtime/PoseProviderSelector.cs:75-78` (`Awake` → `SelectProvider()` once), `:85-131` (single `TryOpenBridge`; only the plugin-missing case warns, a plain `NotReady` is silent at `:123`), `:133-146` (synthetic fallback selected and then never revisited)
  - `unity/Cubeglass/Packages/com.cubeglass.input/Runtime/SyntheticPoseProvider.cs:55-56` (serialized default `TrackState.Stable`), `:220-230` (every emitted sample carries that state)
  - `unity/Cubeglass/Packages/com.cubeglass.input/Runtime/GameplayBridge.cs:459-469` and `:477-506` (quality is taken from the provider/sample; `Stable` ⇒ `TrackingQuality.Stable`)
- **Failure scenario (confirmed code behaviour; trigger suspected/dependent on launch order):** the player starts before `cg-handservice` has created `Local\cubeglass.v1.state`. `cg_bridge_open`'s 50 ms window (ADR-0010) returns `NotReady`, the selector picks the synthetic identity provider, and that is permanent: `SelectProvider` has no production caller after `Awake` (only tests call it; grep of the tree) and no retry timer exists. When the service comes up, the wearer has a static forward view while the bridge writes poses; `TrackingState` is `Stable`, so `GameplayBridge`/interaction never see `NotReady`/`Lost` and never react (no edit cancellation, no UX signal), and the only diagnostic is a flag no runtime UI reads (TD-023). The same happens if the region appears with a newer ABI (`Unsupported` path). In a headset this is the classic disorientation hazard (turning your head while the world does not move). At this HEAD the writer service does not ship, so it is latent for S7; **it becomes Critical for S12 unless the launcher enforces service-before-game and the loss-of-tracking state is surfaced.**
- **Suggested fix:** while `!UsingBridge && !PluginUnavailable`, re-probe periodically (e.g. every 1–2 s, possibly escalating in cost) and switch the latch provider on success; expose `WaitingForBridge` in `DebugOverlay`; map the fallback to `TrackState.Lost` (or `NotReady`) so gameplay degrades instead of believing `Stable`. Tests: a selector test with a fake opener that returns `NotReady` then `Ok`.

### I-2 — World-store durability: no flush before replace; non-atomic fallback window

- **Files/lines:** `unity/Cubeglass/Packages/com.cubeglass.rendering/Runtime/FileWorldStore.cs:494` (`File.WriteAllBytes(temp, …)`), `:499` (`File.Replace`), `:505-510` (fallback `File.Delete(path); File.Move(temp, path);`), `:515` (move-only branch), class claims at `:64-66` and `:79-88`
- **Failure scenario A — power loss / hard reset (confirmed absence of fsync; impact suspected by crash type):** `File.WriteAllBytes` returns once the data is in the OS cache; `File.Replace` persists the rename metadata atomically but the data blocks are not guaranteed to have reached disk. After a power cut, NTFS can replay the rename before the data is durable, leaving the destination zero-length or partially written. The codec then rejects the payload on the next boot (`ChunkDeltaCodec.TryDeserialize` fails) and the chunk regenerates from the baseline: **all edits for that chunk are lost, including edits that were previously saved**, because the old file was replaced. There is no `FileStream.Flush(true)`/`FileOptions.WriteThrough` anywhere in the write path.
- **Failure scenario B — reader during the fallback window (confirmed code; reachability requires `File.Replace` to fail, e.g. non-NTFS/network profile or destination locking that still allows delete):** between `File.Delete` and `File.Move`, `LoadAsync` (`:287`, synchronous on the main thread) can observe no file, return `null`, and `ChunkViewManager.ApplyStoredDelta` silently regenerates the baseline for that load. The edit is not lost on disk, but the session's view is inconsistent until an unload/reload. The class-level claim that a reader "always sees either the old or the new complete file" is false on this path.
- **Suggested fix:** write the temp via `FileStream` with `Flush(true)` (or `FileOptions.WriteThrough`) before `Replace`; retry `Replace` instead of delete+move, or keep a `.bak` and make the fallback a copy-replace; document the durability level. A forced-failure test already exists for the "previous file kept" case; add a crash-consistency test if the store gains a fake FS.

### I-3 — No finite-value guard at the camera-boundary writers (NaN bypasses every clamp)

- **Files/lines:**
  - `unity/Cubeglass/Packages/com.cubeglass.rendering/Runtime/StereoRigConfig.cs:49-79` (IPD/FOV setters use `Mathf.Clamp`, which returns NaN for NaN; `Near`/`Far` are unvalidated), `:132-150` (`Validate` compares values; NaN fails every comparison and passes through)
  - `unity/Cubeglass/Packages/com.cubeglass.rendering/Runtime/StereoRig.cs:134-146` (the "clamp at the point of use" defence has the same NaN hole), `:157-160` (`nearClipPlane`/`farClipPlane` written raw)
  - `unity/Cubeglass/Packages/com.cubeglass.rendering/Runtime/PlayerRoot.cs:77-88` (`SetPlayerPose` writes `transform.position` with no finite check)
- **Failure scenario (confirmed code gap; reachability requires a corrupt/hand-edited scene or a future caller):** Unity scene YAML accepts `.nan`/`.inf` for serialized floats and deserialization bypasses property setters (the code comments at `StereoRig.cs:134-136` explicitly acknowledge this bypass, but the guards used are comparison-based). A `near: .nan` in a scene (or a programmatic NaN) leaves `Camera.nearClipPlane` NaN; a NaN IPD/FOV similarly produces a NaN projection. A NaN internal position from any future `SetPlayerPose` caller makes the camera world matrix NaN. In the glasses this shows as a black, blank or torn image — total loss of usable vision. The pose *rotation* path is already safe: `LateLatchPose.ApplySample` goes through `Quat.FromComponents`/`Invert`, which replace non-finite components with identity (`dotnet/src/CoreMath/Quat.cs`), and `SyntheticPoseProvider` NaN likewise degrades to identity. The committed scenes were read and contain the valid values (`ipdMeters: 0.064`, `fovDegrees: 45`, `near: 0.05`, `far: 500`), so this is a boundary-hardening gap, not a live defect.
- **Suggested fix:** add `float.IsFinite` guards (fallback + one warning) in `StereoRigConfig.Validate`/setters and for `Near`/`Far` (also enforce `far > near`), and finite-check `PlayerRoot.SetPlayerPose` before writing the transform. Tests: programmatic NaN/IPD/FOV/near/far/position cases asserting a finite camera transform and projection.

## Minor findings

### M-1 — Silent no-op if player seeding cannot initialise
`unity/Cubeglass/Packages/com.cubeglass.input/Runtime/GameBoot.cs:137-150`. If `bridge.EnsureInitialized()` returns false (streaming missing/mis-wired, `Views`/`World` null), seeding returns without a log or retry and the player boots at internal origin (far below/inside terrain) instead of the authored spawn. Committed scene is correctly wired, so misconfiguration only. **Fix:** log a warning and retry seeding on the first successful tick, or assert loudly in `Start`. *Confirmed code; misconfiguration trigger.*

### M-2 — Deferred-load and post-upload failure containment
`unity/Cubeglass/Packages/com.cubeglass.rendering/Runtime/ChunkViewManager.cs:541-580`. The generation loop owns no try/catch. If `generator.Generate`/`world.LoadChunk`/`ApplyStoredDelta`/`CompactWorldIfNeeded` throws, the `deferredSet` entry has already been consumed, the chunk may be half-registered (in `world`, not in `chunks`), `scheduler.NotifyMeshReady` is never called, and nothing retries: a permanently missing chunk (a hole in the world) plus a log spam every subsequent frame is not the outcome. Related: `:444-459` — `views.Add` sits outside the try/catch, so an exception there (OOM) leaks the pooled view after a successful upload, breaking the file's own exactly-once claim. **Fix:** wrap the loop, and either re-queue/skip with diagnostics or mark the load failed through the scheduler; move the map insertion inside the guarded region. *Confirmed code; OOM-only trigger.*

### M-3 — Stored-delta load blocks the main thread per generated chunk
`unity/Cubeglass/Packages/com.cubeglass.rendering/Runtime/ChunkViewManager.cs:588-632` (`LoadStoredDelta` → `GetAwaiter().GetResult()`), with `FileWorldStore.cs:287` doing a synchronous `File.ReadAllBytes`. Once per generated chunk (one per frame while streaming in), the main thread performs file I/O inside the frame budget; an AV scan, cold cache or network profile can exceed the 11.1 ms frame. The XML doc acknowledges "loads happen on the main thread", but it is not in the S7-gate deferred list. **Fix:** surface the async load (callback/queue) or apply the delta on the next frame after an async read. *Confirmed code; slow-disk trigger.*

### M-4 — No 32-bit index format for large chunk meshes
`unity/Cubeglass/Packages/com.cubeglass.rendering/Runtime/ChunkViewPool.cs:364-369` uploads positions then `SetIndices` without ever setting `mesh.indexFormat`. Unity's default is 16-bit (65 535 vertices); the greedy mesher has no cap and pathological content (checkerboard edits) could exceed it, where behaviour is version-dependent (community reports of no automatic promotion; the official docs do not promise it). Current terrain is far below the limit, so this is latent. **Fix:** set `IndexFormat.UInt32` when `data.VertexCount > 65535` (with a platform-support note) and add a mesher/upload test that exceeds the limit. *Confirmed absence of guard; suspected reachability.*

### M-5 — Chunk views render with no material and no atlas
`unity/Cubeglass/Assets/Scenes/Game.unity:623` (`viewMaterial: {fileID: 0}`), `ChunkViewPool.cs:319`, `ChunkViewManager.cs:82-123`. No `Material`, `Shader` or atlas texture asset exists anywhere under `unity/Cubeglass/Assets`; the pool assigns `sharedMaterial = null`, so views render with Unity's default material while the mesher's atlas UVs and per-vertex AO (`ChunkViewPool.cs:350, 366-367`) are unused/ignored. The playable slice therefore shows an untextured, flat-shaded world. Not a safety item, but the visual contract ("atlas index" data in `SliceBlockRegistry`) has no consumer. **Fix:** ship an atlas material and assign it in the builder, or document "untextured in S7" explicitly. *Confirmed no material; rendering effect inferred (no GPU run).*

### M-6 — `ClampToUnit` converts ±∞ to NaN
`unity/Cubeglass/Packages/com.cubeglass.input/Runtime/InputMapping.cs:284-301`. The doc says "NaN input is zero", but only `IsNaN` is tested; for `+∞`, `1.0/√∞ = 0` and `∞*0 = NaN`, so the mapper can return a NaN move vector. Downstream `PlayerController.SanitiseMoveComponent` (`dotnet/src/Gameplay/PlayerController.cs:199-217`) contains it (NaN→0, ±∞→±1), so this is defence-in-depth only. **Fix:** reject non-finite components; add Infinity cases to `InputMappingTests`. *Confirmed code; unreachable via the legacy Input axes in practice.*

### M-7 — Game-scene frame-budget lane is not hermetic to a live bridge
`unity/Cubeglass/Packages/com.cubeglass.rendering/Tests/PlayMode/GameFrameBudgetPlayModeTests.cs:83-94`. Unlike `FrameBudgetPlayModeTests` (fixed in #40/M-4) and `GameScenePlayModeTests`, this lane sets only the world overrides; it never sets `PoseProviderSelector.ForceSyntheticForTests` nor asserts `UsingBridge`/`PluginUnavailable`. On a machine with a live writer service, the measured pose path (and the rendered content) depends on that process. **Fix:** force synthetic in `SetUp`, clear in `TearDown`, assert `UsingBridge == false` in the measurement test. *Confirmed code; environment-dependent.*

### M-8 — Scene byte-stability is enforced only by prose
The gate's pins (`Game.unity` blob SHA-256 `2B97305E…7767`, `Calibration.unity` `70F970…A1`) live in `docs/notes/s7-gate.md` / `fixes-unity.md`; **no test** reads or hashes the scenes (grep for SHA/canonical in tests: none). A Unity re-save can drift byte-wise while `GameSceneCompositionTests`/PlayMode tests keep passing, so the documented hash becomes silently stale (TD-025 covers the recipe, not the missing test). I verified both committed blobs exactly match the documented hashes via `git cat-file blob | SHA-256`, so the current pins are correct. **Fix:** add an EditMode test hashing the LF-normalized scene content against a checked-in constant, or a rebuild-and-compare builder test. *Confirmed no automated pin.*

### M-9 — Canonicalizer root tiebreak depends on pre-renumbering fileIDs
`unity/Cubeglass/Assets/Editor/SceneCanonicalizer.cs:179-189`. Equal root names fall through to `.ThenBy(Body)`, and `Body` still contains the old (pseudo-random per save) fileIDs; two same-named roots could therefore canonicalize in different orders across saves. Current builders give every root a unique name, and the committed hashes are stable, so this is latent for future content generators. **Fix:** make the fallback independent of old IDs (e.g., stable structural key) or throw on duplicate root names. *Confirmed latent; not reachable with the committed builders.*

### M-10 — Display mode is requested without validation or read-back
`unity/Cubeglass/Packages/com.cubeglass.rendering/Runtime/WindowManager.cs:95-118`. `numerator = (uint)Mathf.Max(1, targetRefresh)` turns `0` or any negative `TargetRefresh` into a **1 Hz** refresh request; `StereoRigConfig.Validate` never inspects `TargetRefresh` (`StereoRigConfig.cs:132-150`), and `ApplyWindowMode` returns `true` unconditionally after `Screen.SetResolution`, so an ignored or degraded mode is indistinguishable from success. The missing-display path is handled (clamped index, `Screen.currentResolution` fallback `:97-103`). For non-main displays the code sizes the window from `Display.displays[index]` but never activates/moves the window there (`Screen.SetResolution` targets the current display); S6-HIL documents the operational workaround ("move the window to it at OS level"), so this is a documented constraint rather than a silent trap — but the tooltip/API still promises more than it delivers. Config is not loaded at runtime yet (TD-014), so the 1 Hz path is latent. **Fix:** validate `TargetRefresh` into a sane range at `StereoRigConfig.Validate`, read back `Screen.currentResolution.refreshRateRatio`/`Screen.fullScreenMode` next frame and warn on mismatch; either implement `Screen.MoveMainWindowTo`/`Display.displays[i].Activate()` or fail loudly when the target display is not current.

### M-11 — World-name validation misses Windows reserved names and case collisions
`unity/Cubeglass/Packages/com.cubeglass.rendering/Runtime/FileWorldStore.cs:613-621`. `ValidateWorldName` rejects separators and invalid filename characters but not reserved device names (`CON`, `NUL`, `COM1`, …), and is case-sensitive while Windows paths are not, so `Default` and `default` address the same directory. Only `default` is used in production today. **Fix:** reject reserved names and normalise case for the collision check, with a clear exception instead of a raw `IOException` from `CreateDirectory`. *Confirmed code; no current trigger.*

## Verified-sound areas (with evidence)

1. **Bridge ABI and P/Invoke (5.12):** `BridgeTypes.cs` uses explicit offsets matching `contracts/cg_types.h` (`cg_head_sample` 48 B, `cg_hand` 272 B, `cg_hand_frame` 576 B, hand joints at 8+12·i, velocity at 260; enum values `BridgeStatus`/`TrackState` identical to the C enums; `cg_hand_frame` laid out as `Hand0`/`Hand1` so marshalling is blittable). `NativeBridge.cs` pins `Cdecl` + `ExactSpelling`, uses `out`/`ref` for every pointer, guards `_handle != IntPtr.Zero` in both `ReadHead` and `Dispose` (double-close safe; no managed use-after-close), and maps the status word 1:1. `NativeBridgeTests` pin sizes, round-trip, staleness at the 250 ms boundary, torn/stress reads and double-close; `NativeBridgeStressTests` exercises 8 readers against the native test writer.
2. **Pose → camera frame safety:** `LateLatchPose` subscribes `Camera.onPreCull` in `OnEnable`, unsubscribes in `OnDisable`/`OnDestroy` (idempotent), dedupes reads by `Time.frameCount` so **both eyes always receive the same sample in a frame**, ignores non-rig `Game` cameras when a rig is set, and applies only rotation (3DoF) through `Quat.FromComponents(…).Normalize()` with a non-finite guard. `BridgePoseProvider` is a thin read wrapper; native staleness is converted at `TrackState.Lost` while the last sample is retained (documented ADR-0010 behaviour), and `LateLatch` keeps the last good pose when the reader returns false. `Recentre` is baseline-based and order-correct (`OnProviderChanged` re-baselines). Sign conventions are pinned to ADR-0004: `UnityConvert.ToUnity` is the single flip (`Quat` `(w,−x,−y,z)`, `Vec3` `(x,y,−z)`), game forward `(0,0,1)` maps to internal `(0,0,−1)`, positive internal yaw looks left, and `PlayerRoot.Heading`/`GameBoot` spawn yaw (`−atan2(x,z)`), `GazeTargeting`, `SyntheticPoseDrive` and `GameplayBridge` snap (`−snap·Deg2Rad`) all agree; `RigMathTests`/`PlayerRootTests`/`InputMappingTests` pin the conversions.
3. **Comfort invariants:** snap turn clamps ±inf/NaN and wraps; the bridge applies the signed step exactly once per edge and moves the root, never the head (snap cannot be overwritten by the next pose); the vignette opacity is monotone between `minSpeed`/`fullSpeed`, capped at `maxOpacity`, and non-finite inputs yield 0 rather than a worse-than-max tint; `MotionVignette` destroys its generated texture. The known SBS-halving of the vignette is TD-026.
4. **Streaming ↔ view manager:** the scheduler enforces per-frame load/unload/mesh budgets and puts rejected uploads back for a later frame; the `ChunkViewManager` upload counter is shared by scheduled uploads and dirty remeshes (dirty remeshes run first, so the scheduler sees the remainder); `ChunkChanged` fan-out is deduplicated through `dirtySet`/`dirtyQueue`; unload/load churn of deferred chunks was traced through the queue/set bookkeeping (no lost load, no double generate); compaction preserves live chunk data, drops per-chunk storage of evicted chunks and rebuilds from the live set; `GameplayBridge.RefreshWorld` re-resolves the world after compaction before the gameplay tick; `World.LoadChunk` replaces duplicates, so a reload cannot leave a stale chunk instance in the world.
5. **Memory/lifecycle:** `ChunkViewPool` maintains the created/active/pooled invariant, throws on double release, and `Upload` releases every `MeshData` in a `finally` (correct also for foreign/released data); the remesh path releases the view on throw (fixed in #40) and the deferred-load/scheduler paths were checked; `ChunkViewManager.DisposeState` is idempotent and unsubscribes `world.ChunkChanged`; `StreamingRuntime` rebuilds cleanly through `Configure`; `GameBoot` disposes the store in `OnDestroy` (pump drains, waiters complete) and `SaveBatches` flushes on pause/quit with a bounded wait.
6. **Persistence concurrency:** `FileWorldStore` serialises writes through one pump; `SaveAsync` serialises the delta (a copy — `ChunkDelta` copies the edit map and `ChunkDeltaCodec` writes bytes) before enqueueing, so queued payloads cannot alias later mutation; coalescing replaces queued bytes and serialises same-chunk writes; `FlushAsync` completes only at `outstandingWrites == 0` and reports latched failures on both the immediate and drained paths; corrupt files are rejected and regenerate the baseline; `SuccessfulWrites`/`FailedWrites` and forced-failure tests (`PersistencePlayModeTests`) pin the behaviour; paths are invariant-culture and confined under `persistentDataPath` (or the test override root).
7. **Editor/build determinism:** both builders create objects in fixed order with fixed names/values; `SceneCanonicalizer` walks settings by class id + `SceneRoots` deterministically, renumbers 1..N, throws when any document is unreachable or `SceneRoots` is missing, and writes UTF-8 without BOM; committed scene GUIDs all resolve to checked-in metas (17 MonoBehaviour references each scene, all found), 107 metas with zero duplicate GUIDs, `EditorBuildSettings` order `[Game, Calibration]` matches the metas, `BuildPlayer` derives its output path from the project root and exits non-zero on failure; `sync-unity-plugins.ps1` stages all five managed DLLs and the native bridge test build.
8. **Scene integrity:** recomputed via `git cat-file blob HEAD:<path>` + SHA-256 (byte-exact, LF): `Game.unity = 2B97305E45F6E8B5ED130B33F6DBC6F589B2DB8278C3E063B7A72DF3A0627767`, `Calibration.unity = 70F970CE7CFEEDC6A70AD27B8759CE177A496A235E59E45E37E0A243E8E490A1` — both match the pins recorded after the #40 fix wave. Serialized rig/window/input/comfort values match the code defaults and the FOV-baked cameras are the expected SBS layout (L−0.032/R+0.032, vertical FOV 26.231289° at 16:9, near 0.05/far 500, target display 0).
9. **Test integrity (positive):** no `[Ignore]`/`Assert.Ignore`/`[Explicit]`/platform gates in project tests; 109 `[Test]` + 44 `[UnityTest]` checks (consistent with the gate's 112/44 after parameterised cases); budget lanes assert the exact frame counts before reporting (no zero-frame vacuity) and label their numbers CPU-side/headless in the XML docs; `GameScenePlayModeTests` is hermetic (world/root overrides + forced synthetic + auto-update off after the boot frame) and asserts the boot fall/settle, edit→remesh→save→unload→reload round trip and the non-bridge selection; registry values are pinned against `blocks.json`; the native stress suite pins no-torn-read.
