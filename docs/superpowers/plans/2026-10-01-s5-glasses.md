# Cubeglass S5 — Glasses Adapter and Head Pose: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `cg-glasses` delivers a reliable `IHeadPoseSource` — `VitureHeadPoseSource` over an isolated SDK seam, plus `FakeHeadPoseSource` and `ReplayHeadPoseSource` — `IDisplayControl`, the `cg-pose-probe` tool, contract/fault/TSan/soak tests and a wait-free-read benchmark. HIL log and ADR answers for U-01/U-08 are owner-executed (dossier §11.5 escalation) and gate the `stage-5-complete` tag, not the software work.

**Architecture:** `contracts/cpp/ports.hpp` adds dossier 5.2 verbatim (`HeadSample`, `IHeadPoseSource`) plus `Duration`, `TrackState`; `contracts/cpp/result.hpp` formalises the §4.2 `Result<T>`/`Status` vocabulary (additive contract files, recorded in ADR-0009). `cpp/glasses` (adapter layer: threads and file IO permitted) isolates every SDK symbol behind `IVitureApi`, a function-table seam; the real loader binds the vendor DLL by name, tests bind a programmable fake. A single writer publishes `HeadSample`s into a wait-free double-buffer slot; `TryGetLatest` never locks, blocks or allocates. SDK seconds map to `HostTime` once, through `core_math::ClockMapper`. `cpp/tools/pose_probe` is the HIL instrument.

**Tech Stack:** C++20 (MSVC 18 locally, GCC in CI), CMake presets + vcpkg (gtest, rapidcheck, benchmark already pinned), Ninja on Linux, TSan preset, gcovr/ASan/UBSan lanes unchanged.

**Spec:** `Cubeglass_Engineering_Dossier.md` — 0 (rules), 2.1 (facts F-01/F-02/F-04), 3.2/3.3 (module table, dependency rule, D-1), 3.6 (conventions), 4.2/4.4, 5.1 (`cg_types.h`), 5.2 (port verbatim), 6/S5 (deliverables, work items, tests, exit gate), 7 (test matrix), 9 (CI), 11 (protocol), 12/A (ADR list), R-08. `docs/questions/README.md` governs the HIL escalation.

## Global Constraints

- Contracts frozen: `contracts/cg_types.h` unchanged; `ports.hpp` reproduces 5.2 verbatim; `result.hpp`/`Duration`/`TrackState` are additive and recorded in ADR-0009.
- `cg-glasses` is an adapter: threads, `windows.h`, file IO and the SDK seam are allowed; it must not link ONNX Runtime or engine code (`contracts/layers.json` gains a `cg-glasses` entry forbidding `onnxruntime`).
- Units/conventions per ADR-0004: SDK pose `float[7]` → `PoseFromSdk`; SDK seconds → `ClockMapper` → `HostTime`; sequence strictly monotonic per source.
- `TryGetLatest` wait-free: no locks, no allocation, no blocking (proved by a benchmark and an allocation-counter test).
- Every SDK call goes through `IVitureApi`; no other translation unit includes a vendor header.
- TDD for every task; Conventional Commits; the HIL work item halts per `docs/questions/` (hardware absent in the build environment).

## Review Focus

1. **Stop is total**: after `Stop()` returns, no new sample is observable, the thread has joined, and the destructor is safe (also when never started). Pinned in Tasks 1–3.
2. **Torn-read impossibility**: readers must never observe a mismatched (pose, time, seq) or a non-normalised quaternion while the writer publishes, under TSan and stress. Pinned in Task 3.
3. **Fault handling**: SDK errors, device removal mid-stream and long stalls surface as `Result` errors or degraded states — never crashes, hangs or unbounded retry storms; `Start` failure leaves the object reusable. Pinned in Task 2.
4. **Recentre semantics**: `Recenter` zeroes yaw within tolerance and leaves pitch/roll continuous (F-04); it is idempotent and thread-safe against the polling thread. Pinned in Tasks 1–2.
5. **Replay fidelity**: replay reproduces the CSV's poses/states/timing exactly (same order, no dropped/duplicated rows), so S8+ datasets are trustworthy. Pinned in Task 3.

- Contract suite (`contract_tests.cpp`) parameterised over factories and written to run against fake now and Viture/replay later: Start idempotent; Stop idempotent and total (no sample observable after Stop until restarted); `TryGetLatest` false before first sample; sequence strictly increasing; time strictly increasing; pose finite and unit quaternion; Recenter zeroes yaw within 0.1° and preserves pitch/roll within 0.1°; `predict=0` returns the newest sample verbatim; predict extrapolates yaw in the sweep direction; restart after Stop resumes sequence ordering.

### Task 2: Viture SDK seam, RAII wrapper and polling source (S5-WI2..5)

- Create: `cpp/tests/glasses/fake_viture_api.hpp`, `viture_fault_tests.cpp`, `viture_contract_tests.cpp` (runs the Task 1 suite against the Viture source over `FakeVitureApi`)
- Modify: `cpp/glasses/CMakeLists.txt`, `cpp/tests/glasses/CMakeLists.txt`
- Commit(s) at the implementer's discretion

**Interfaces:**
- `IVitureApi` (pure virtual, no vendor headers anywhere else): `Result<void> CreateDevice()`, `void DestroyDevice() noexcept`, `Result<void> StartPose()`, `Result<cg_head_sample> PollPose()` (blocking up to a documented timeout), `Result<void> ResetOriginCarina(const float pose[7])`, `Result<void> SetDisplayMode(uint32_t refresh_hz, bool sbs)`, `Result<uint32_t> GetRefreshHz()`, `std::string SdkVersion() const`. All calls documented: poll blocks on the SDK's own thread model; nothing here is called from readers.
- `viture_loader`: `Result<std::unique_ptr<IVitureApi>> LoadVitureApi(const std::string& dll_path)`; Windows `LoadLibraryW`/`GetProcAddress` (path from `CG_VITURE_DLL`, default `viture_glasses_sdk.dll`), POSIX `dlopen` (for CI-only compile checks); unresolved symbols → `Unsupported` with the missing name in the message. The real function-table binding lives in this one TU.
- `VitureHeadPoseSource` (implements `IHeadPoseSource`): owns `IVitureApi` (injected), `ManualClock`-free real time via an injectable `IHostClock` (defaults to `std::chrono::steady_clock`), `ClockMapper`, `PoseSlot`, one `std::jthread`; polling loop: `PollPose` → map status (stable/unstable/lost, with an unstable-timeout policy of 500 ms before declaring Lost) → `PoseFromSdk` → `Mapper.Map(sdk_seconds)` → publish with `seq+1`; thread named (`SetThreadDescription` on Windows) and raised priority via an injectable hook (no-op default); `Stop` requests stop, joins, idempotent; reconnect policy: on `Device`/`Timeout`, destroy, wait a backoff (100 ms doubling to 2 s), recreate/restart, capped attempts (10) then `Lost` state until a successful poll; `Recenter` calls `ResetOriginCarina` with the current pose's `float[7]`.
- Fault tests: create failure → `Start` returns the error and a second `Start` retries cleanly; poll errors → reconnect attempts observed on the fake (count/backoff pin); removal mid-stream → state transitions `Stable→Unstable→Lost` within the policy; a blocking `PollPose` (fake sleeps) must not delay `TryGetLatest` or `Stop` beyond one poll timeout (fake respects a stop flag); `Recenter` failure surfaces as `Result` error.

- [ ] **Step 1: RED**; **Step 2: implement**; **Step 3: GREEN**, run the contract suite against the Viture source over the fake API plus fault tests; full serial run + `ci-local -SkipUnity`; commit.
