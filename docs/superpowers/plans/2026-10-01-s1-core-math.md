# Cubeglass S1 — Core Math, Time and Conventions: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One tested implementation of coordinate conventions, transforms and clocks shared by C++ (`cg-core-math`) and C# (`Cubeglass.CoreMath`), pinned by a shared golden fixture file, tagged `stage-1-complete`.

**Architecture:** Two parallel, dependency-free implementations of the same value types (`Vec3`, `Quat`, `Pose`) over `double`, with identical formulas so both consume `contracts/golden/transforms.json` within 1e-6. Conversions happen at exactly two boundaries: SDK pose (`float[7]`, layout `[px,py,pz,qw,qx,qy,qz]`) into the internal pose, and internal pose into Unity's left-handed convention. `HostTime` is `int64` nanoseconds; `ClockMapper` turns SDK seconds into `HostTime` with a sliding-window median offset. Nothing here allocates on hot paths, and the modules stay free of IO, threads and engine types.

**Tech Stack:** C++20 (MSVC 18 locally, GCC in CI), CMake + presets + vcpkg (pinned baseline), GoogleTest, rapidcheck (property tests), nlohmann-json (fixture parsing in tests), Google Benchmark; .NET 10 test project consuming a netstandard2.1 library (`LangVersion 9.0`), NUnit, System.Text.Json, coverlet; Python depcheck gates.

**Spec:** `Cubeglass_Engineering_Dossier.md` — section 0 (rules), 3.6 (conventions), 4.2 (tooling), 4.4 (test strategy), 5.1 (`contracts/cg_types.h`), 6/S1 (deliverables, work items, required tests, exit gate), 7 (test matrix), 11 (operating protocol). ADR-0004 is created here.

## Global Constraints

- C++20; warnings as errors (`-Wall -Wextra -Wpedantic -Wconversion -Werror`, MSVC `/W4 /WX`); no raw owning pointers; no exceptions across module boundaries; `Result<T>` only where an operation can fail — all S1 operations are total, so they return values, not `Result`.
- C# nullable enabled, warnings as errors, `netstandard2.1` + `LangVersion 9.0` for `Cubeglass.CoreMath` (block namespaces only); test project `net10.0` may use modern syntax.
- Pure modules must not reference the engine, the VITURE SDK, ONNX Runtime, the file system or threads. `contracts/layers.json` already forbids `thread`, `fstream`, `filesystem`, `mutex` includes (C++) and `System.IO`, `System.Threading` namespaces (C#); do not add to those lists.
- Units: metres, seconds, radians; pixels top-left. Axes: right-handed, Y up, forward **-Z**, X right. Quaternion storage `(w, x, y, z)`, always unit.
- `HostTime` is `int64` nanoseconds on one monotonic timeline; SDK `double` seconds convert once, through `ClockMapper`.
- Contracts are frozen. This plan **adds** `contracts/cg_types.h` exactly as section 5.1 defines it and introduces `contracts/golden/transforms.json`; no existing contract file changes.
- Hot paths (all value operations, conversions, `ClockMapper`) allocate nothing. Measured by counter tests, not by inspection.
- TDD for every task: failing test first, minimal implementation, green, commit. Conventional Commits. No TODO without a linked issue.
- This plan implements S1 only. S2 starts only after `stage-1-complete` is tagged.

## Review Focus

1. **Degenerate quaternion input** (`(0,0,0,0)`, NaN, infinity, huge magnitudes): `Quat.FromComponents`/`PoseFromSdk` must return a unit quaternion (identity for non-finite or near-zero norm) — never NaN, never a zero quaternion. Pinned in Tasks 2, 3 and 6.
2. **Slerp at the edges** (`t=0`, `t=1`, dot near +1 or -1, opposite quaternions): endpoints must be exact, no divide-by-zero, shortest path taken. Pinned in Tasks 2 and 6.
3. **ClockMapper before the window is full and while it drifts**: error ≤ 1 ms under jitter and drift; `Map` deterministic; eviction of old samples must not change the answer twice. Pinned in Tasks 4 and 7.
4. **Yaw direction sign in the Unity conversion**: a right-hand-rule +90° yaw about +Y in internal space must become -90° yaw in Unity. The `-z`/`(w,-x,-y,z)` flip is easy to negate the wrong way; pinned by explicit cases in Tasks 3, 6 and the golden fixture.
5. **Cross-language numeric agreement**: both languages consume the same fixture and own the exact same formulas; the fixture contains only hand-derivable exact values (halves, 0/±1, 22.5° sines) so a wrong value cannot be self-consistent across both. Pinned in Tasks 5 and 8.

  - `Slerp`: `d = Dot(a,b)`; if `d < 0` then `b = -b`, `d = -d`; if `d > 0.9995` linearly interpolate componentwise and normalise; else `θ = acos(d)`, `s1 = sin((1-t)θ)/sin(θ)`, `s2 = sin(tθ)/sin(θ)`, result `Normalize(s1*a + s2*b)`. Output normalised in all branches; `t=0`/`t=1` exact.
