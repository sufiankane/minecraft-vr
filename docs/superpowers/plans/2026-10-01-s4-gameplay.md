# Cubeglass S4 — Input Abstraction and Gameplay Logic: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Cubeglass.Gameplay` implements dossier 5.11 — an input abstraction, a player controller with gravity/collision, an interaction service (target, hold-to-break, place, hotbar, tracking-loss cancellation, recentre), explicit state machines, JSON-replayable regression scenarios, and a first gesture recogniser over mock hand joints — with every scenario green in plain `dotnet test` and coverage ≥ 90 %, tagged `stage-4-complete`.

**Architecture:** One netstandard2.1 pure assembly `Cubeglass.Gameplay` (references CoreMath + Voxel only; no engine/IO/threads). Contract 5.11 defines `IInputProvider`, `InputFrame`, `IGestureRecognizer`, `IInteractionService`; the dossier never defines the supporting types (`PointerRay`, `ButtonState`, `TrackingQuality`, `HandsInput`, `GestureOutput`, `InteractionResult`, `PlayerState`), so ADR-0008 defines them additively, together with the tuning constants (walk speed, gravity, reach, break-time formula, hysteresis, 200 ms tracking-loss rule). Services are pure functions of `(input, world, player, dt)`; `IWorld.Apply` remains the only world mutation. JSON scenario scripts are test assets parsed by the test project (no JSON dependency in the library).

**Tech Stack:** netstandard2.1 + C# 10 + IsExternalInit polyfill; NUnit; FsCheck (already pinned); System.Text.Json in tests only; coverlet + depcheck floor 90 for `Cubeglass.Gameplay`.

**Spec:** `Cubeglass_Engineering_Dossier.md` — 0, 3.3, 4.2/4.4, 5.9 (IWorld/EditCommand), 5.11 (input/gameplay contracts + behaviour rules), 6/S4 (deliverables, work items, tests, exit gate), 7, 11. ADR-0004/0005/0006/0007 apply.

## Global Constraints

- Pure module: no `UnityEngine`, `System.IO`, `System.Threading`; allowed references `Cubeglass.CoreMath` + `Cubeglass.Voxel` only.
- Contract 5.11 verbatim for the four interfaces/structs it defines; everything else additive and recorded in ADR-0008.
- `IWorld.Apply` is the only world side effect; `IInteractionService.Update` must never allocate on its hot path and must be deterministic for the same inputs.
- Fixed timestep (`dt` supplied by the caller), no clocks inside services; time in seconds, `HostTime` for logs only (S5+).
- Tracking loss longer than 200 ms cancels in-progress break/place (dossier 5.11).
- TDD; Conventional Commits; contracts frozen (additive types only).

## Review Focus

1. **Tracking-loss cancellation at the 200 ms boundary**: break/place progress resets exactly once, at the first frame past 200 ms of loss, and never applies an edit from stale input. Pinned in Task 2.
2. **Placement legality**: cannot place inside the player AABB, only against a solid face into an air/replaceable target; a rejected command mutates nothing. Pinned in Task 2.
3. **Determinism**: same scenario script + seed → identical final world hash and player state, independent of frame chunking (`dt` split invariance within a documented tolerance for movement). Pinned in Tasks 1 and 2.
4. **Break-time formula and hotbar cycling**: hardness → seconds per ADR-0008; hotbar wraps at both ends; cycling during a break keeps the break on the original target. Pinned in Task 2.
5. **Gesture hysteresis**: thresholds have separate enter/exit values; a signal hovering at the boundary cannot oscillate; tracking loss clears gestures. Pinned in Task 3.

**Interfaces (ADR-0008 pins the semantics):**
- `enum ButtonState { Up, Pressed, Held, Released }`; `enum TrackingQuality { None, Degraded, Good }`.
- `readonly record struct PointerRay(Vec3 Origin, Vec3 Direction)` with `bool TryToRay(out Voxel.Ray)` normalising finite nonzero directions.
- `InputFrame` exactly as 5.11 (fields in that order; default = neutral frame).
- `HandsInput` (minimal S4 shape, documented as extended by S11): `bool Tracked`, `HandFrame? Left`, `HandFrame? Right`; `HandFrame` = `Vector3f Wrist, ThumbTip, IndexTip, MiddleTip, RingTip, LittleTip`.
- `GestureOutput`: `bool Pinching`, `bool Fist`, `bool PaletteFlick`, `float PinchStrength` (0..1); default all false/0.
- `InteractionResult`: `bool BreakInProgress`, `float BreakProgress` (0..1), `bool Edited`, `Int3? Target`.
- `PlayerState` (mutable struct or class? choose a `sealed class` for reference semantics; ADR records): `Vec3 Position` (feet centre), `Vec3 Velocity`, `float YawRadians`, `float PitchRadians`, `bool OnGround`, `int HotbarIndex`, `Aabb Body` (derived: half extents 0.3 × 0.9 × 0.3, feet at Position).
- `Hotbar`: fixed 9 slots, `BlockId Selected`, `void Cycle(int delta)` (wraps), `BlockId Get(int slot)`; default contents Stone/Dirt/Grass/Sand/Wood.
- `ScriptedInputProvider : IInputProvider` — constructed from `IReadOnlyList<(double time, InputFrame)>` or a mutable timeline API; `Sample(time)` returns the most recent frame at or before `time` (pure, deterministic).
- `PlayerController.Step(PlayerState, in InputFrame, IWorld, double dt)`: yaw/pitch from `TurnSnap` (snap degrees) and `Move`; horizontal velocity = move direction × walk speed (yaw-relative), vertical gravity `-25 m/s²`, jump not in S4 (documented); collision resolved per axis using `VoxelCollision.Overlaps` with the player AABB (step-up not required; pin axis order X→Z→Y and sliding).
- ADR-0008 constants: walk speed 4.5 m/s, gravity −25 m/s², terminal fall −40 m/s, `TurnSnap` is degrees per second applied to yaw (pointer devices use pointer/mouse later; S4 keyboard only), reach 5.0 m, break time `seconds = max(0.05, hardness)` (hardness from `BlockDefinition`, e.g. stone 1.5 s), placement/break repeat rates, hotbar 9 slots, pinch enter 0.7/exit 0.5, fist enter 0.6/exit 0.4, palette flick window 250 ms, tracking-loss timeout 200 ms.

### Task 2: Interaction service and scenario replays (S4 WI2..4)

**Branch:** `s4/interaction` (after Task 1 merges).

**Files:**
- Create: `dotnet/src/Gameplay/IInteractionService.cs`, `InteractionService.cs`, `BreakState.cs`, `InteractionState.cs`
- Create: `dotnet/tests/Gameplay.Tests/InteractionServiceTests.cs`, `InteractionScenarios.cs`, `scenarios/*.json` + `ScenarioRunner.cs` (test-only JSON parsing with System.Text.Json)
- Commit(s) at the implementer's discretion

**Interfaces:**
- `IInteractionService` verbatim from 5.11; `InteractionService` holds a `DdaRaycaster`.
- State machines as explicit enums + transition tables: `InteractionState { Idle, Breaking, Placing }` with a documented transition table; `BreakState` per target cell (accumulated time).
- Target selection: `input.Pointer` (else the player's view ray derived from yaw/pitch) cast via `DdaRaycaster` within reach 5 m; `Target` in the result is the hit cell.
- Break: while `Primary` is `Held` on a solid target, accumulate `dt`; at `max(0.05, hardness)` seconds, apply `EditCommand(cell, expected: block, new: Air)`; reset progress on target change, button release, or tracking loss > 200 ms. `BreakProgress` is `accumulated / required` clamped.
- Place: `Secondary` `Pressed` (edge) with a solid target applies `EditCommand(cell + normal, expected: Air, new: hotbar.Selected)` unless the target cell `CanPlace` is false against the player AABB; rejected placements produce no edit and keep state `Idle`.
- Hotbar: `HotbarDelta` cycles slots on the `PlayerState` (via the service interface? `PlayerState` is passed by value in 5.11 — change to a mutable class in Task 1 so cycling persists; ADR-0008 records the decision).
- Tracking loss: `Quality == None` starts a loss timer; once > 200 ms, any in-progress break resets and pointer input is ignored; recovery re-arms cleanly. Exactly one reset at the boundary frame; no edit on the boundary.
- Scenario scripts (JSON, parsed in tests): one per required scenario — walk, break (incl. hardness timing), place, place-inside-player rejection, tracking-loss cancel, hotbar cycle mid-break, recentre request (`input.RecenterPressed` sets `PlayerState.YawRadians = 0` per FR-08 and records it in `InteractionResult`/state; S5 wires the SDK). Each script has fixed `dt`, a frame list, seed, and asserts final world hash + selected observations; the runner replays via `ScriptedInputProvider`.
- Property (FsCheck): for random input sequences, every applied edit goes through `IWorld.Apply`, no edit is applied while tracking is lost > 200 ms, and replaying an accepted-command model reproduces the world hash.

- [ ] **Step 1: RED**; **Step 2: implement**; **Step 3: GREEN**; full suite + `ci-local -SkipUnity`; commit.
