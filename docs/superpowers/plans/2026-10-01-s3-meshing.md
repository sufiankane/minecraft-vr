# Cubeglass S3 — Meshing: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Cubeglass.Mesh` implements dossier 5.10 — a reference culling mesher, a greedy mesher that matches it on surface area for thousands of random chunks, per-vertex AO, border handling via neighbour snapshots with dirty propagation, buffer pooling with zero allocations after warm-up, and a benchmark suite whose p95 meets the stage budget — tagged `stage-3-complete`.

**Architecture:** `Cubeglass.Mesh` (netstandard2.1, pure, references CoreMath + Voxel only) holds `IChunkMesher`, `MeshData` (SoA pooled buffers), `CulledMesher` (reference), `GreedyMesher`, `AtlasLayout`/`AtlasMap`, and a `MeshBufferPool`. `NeighbourSnapshot` and the dirty-propagation rule live in `Cubeglass.Voxel` (chunk data). `Vector3f`/`Vector2f` are added to `Cubeglass.CoreMath` (float interchange types the contract names but never defines). ADR-0007 pins the budget, winding, AO encoding, atlas mapping, neighbour scope and dirty rules.

**Tech Stack:** netstandard2.1 + C# 10 (`LangVersion 10.0`, IsExternalInit polyfill already exists in Voxel; CoreMath stays C# 9 with hand-written readonly structs), NUnit, FsCheck, BenchmarkDotNet, coverlet + depcheck (floor 90), FNV-1a mesh hashes in tests.

**Spec:** `Cubeglass_Engineering_Dossier.md` — section 0, 3.3, 4.2/4.4, 5.10 (mesh contract verbatim), 6/S3 (deliverables, work items, tests, exit gate), 7, 8, 9, 11. Prior stages: S1 CoreMath, S2 Voxel (ADR-0005/0006).

## Global Constraints

- Pure modules: no `UnityEngine`/`UnityEditor`, `System.IO`, `System.Threading`; `contracts/layers.json` already grants `Cubeglass.Mesh` exactly `Cubeglass.CoreMath` + `Cubeglass.Voxel` references.
- `IChunkMesher.Build(ChunkSnapshot chunk, NeighbourSnapshot neighbours, IBlockRegistry blocks)` and `MeshData` fields exactly as 5.10; `MeshData` is engine-neutral and pooled.
- Invariants: no internal faces between two opaque blocks; a fully solid chunk merges to the minimum quads; same input → byte-identical output; no allocations after pool warm-up.
- Units/conventions from ADR-0004 apply. Winding and AO encoding are pinned by ADR-0007.
- TDD for every task; Conventional Commits; contracts frozen (additive types only, recorded in ADR-0007).

## Review Focus

1. **Differential truth**: greedy and reference must cover identical visible surface area (same set of exposed block faces) on thousands of seeded random chunks — not merely similar counts. Pinned in Task 2.
2. **Seams and borders**: an edit on a chunk border must mark every affected neighbour dirty (chunk + 26-neighbourhood rule) and both sides of the seam must mesh without gaps or duplicated/missing faces. Pinned in Task 3.
3. **AO correctness**: AO values must be identical regardless of which chunk built the quad (no seam light steps), and AO must be independent of traversal order. Pinned in Task 3.
4. **Byte-identical determinism**: same input → identical `Positions/Normals/Uvs/Ao/Indices` bytes across runs, instances and pool states. Pinned in Tasks 2/3/4.
5. **Zero allocations after warm-up**: pooled `Build` allocates nothing measurable once the pool is warm; `MeshData.Release()` returns buffers exactly once (double-release is rejected). Pinned in Task 4.

- `NeighbourSnapshot`: read-only view of the 26 neighbouring chunks: `ChunkSnapshot? Get(Int3 direction)` for each direction with components in `{-1,0,1}` (excluding zero); static `Empty`; `BlockId GetCell(Int3 worldCell)` helper resolving through the right neighbour (returns `Air` when the neighbour is missing). `World` gains `NeighbourSnapshot CreateNeighbourSnapshot(ChunkCoord)` (additive).
- `ChunkEditPropagation.GetAffectedChunks(Int3 cell)` → `IReadOnlyList<ChunkCoord>`: every chunk containing any cell of `cell + [-1,1]³` (1, 2, 4 or 8 chunks), sorted deterministically; documented rule (an edit changes face visibility of face-adjacent chunks and AO of edge/corner neighbours).
- ADR-0007 pins: p95 budget **≤ 2.0 ms per full 16³ chunk** measured on the dev machine by the Task 4 harness (with nightly regression thresholds deferred); winding; AO encoding (`byte` 0..255 quantised from 4 levels, 0 = most occluded, formula to be pinned by Task 3 tests); atlas mapping (no padding in S3); neighbour scope (26); dirty rule (from `ChunkEditPropagation`); and the additive types above.

**Branch:** `s3/ao-borders` (after Task 2 merges).

**Files:**

- Commit(s) at the implementer's discretion

**Interfaces:**
- AO levels 0..3 from the standard 3-neighbour rule per corner (side1, side2, corner): `level = (side1 && side2) ? 0 : 3 - (side1?1:0) - (side2?1:0) - (corner?1:0)`; quantise to `byte` (0,85,170,255) — pin exact mapping in ADR-0007 and tests.
- `Ao` stream has one byte per vertex; vertex order per quad is fixed (pin in ADR/goldens).
- Border handling: `IChunkMesher.Build` reads neighbour cells through `NeighbourSnapshot` (faces with opaque neighbour cells are culled; AO at borders uses neighbour cells), and `ChunkEditPropagation` drives dirty marking (the propagation rule itself is Task 1's; Task 3 tests the seam behaviour).
- Tests: AO hand cases (open corner 3, one side occluded 2, two sides 1, corner+sides 0); rotation/reflection symmetry; AO identical when computed from either side of a border (no seam step) for random border edits; seam test: build both chunks, edit a border cell, rebuild the affected neighbour(s) per `ChunkEditPropagation`, assert no gap (exposed-face multiset over the union of both meshes equals the reference computed on an equivalent monolithic chunk for a 32×16×16 world); golden hashes updated for AO (record new constants).
- Determinism: byte-identical output across traversal instances and pool states.
