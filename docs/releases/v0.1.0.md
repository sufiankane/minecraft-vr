# Cubeglass v0.1.0 — M1 vertical slice (release candidate)

**Status:** release candidate. The `v0.1.0` tag is **withheld** until the S7
HIL playtest on the glasses is committed and the CI player build succeeds
(controller ruling R50; see [`../questions/S7-HIL.md`](../questions/S7-HIL.md)).

M1 is the first playable vertical slice: a deterministic voxel streaming
runtime, a gamepad/keyboard-driven player with gaze interaction, batched local
persistence, and the committed Windows game scene, all inside the ADR-0010
90 Hz frame budget.

## What is in M1

- **Deterministic streaming.** `Cubeglass.Streaming` is a pure module (no
  engine/IO/threads): an eight-chunk view distance with two-chunk unload
  hysteresis, nearest-first priority, and per-frame load/unload/upload budgets.
  The scripted 5-minute golden session hashes to
  `0xB38A50148C01A643` and is frame-chunking independent.
- **Chunk views.** Pooled GameObjects/Meshes with a bounded per-frame upload
  queue, one-chunk-per-frame generation, `MeshData.Release()` exactly once per
  mesh, and dirty-remesh propagation through `World.ChunkChanged`.
- **Gameplay and input.** Gamepad (left stick move, right stick turn, A place,
  X break, Y recentre, LB/RB hotbar, D-pad left/right snap) and keyboard/mouse
  (WASD, mouse look, LMB/RMB, Q/E, R recentre, F snap right / Shift+F snap
  left) providers produce identical input frames; gaze targeting is the
  eye-midpoint camera forward; edits run through the pure DDA interaction
  service.
- **Comfort and UI.** Edge-triggered 45° snap turn, speed-ramped motion
  vignette (off when stationary), world-locked reticle and an eye-height hotbar
  strip inside the per-eye vertical FOV (the feet-anchored off-screen placement
  was fixed in the S7 review round).
- **Persistence.** A Unity `FileWorldStore` over the S2 chunk-delta codec with
  atomic temp+rename publication and a background writer; edits flush in
  batches (32 edits or 2 s) and on quit/pause; stored deltas replay at boot
  over the generated baseline and merge with in-session edits.
- **Scenes.** `Assets/Scenes/Game.unity` (playable slice) and
  `Assets/Scenes/Calibration.unity` (stereo reference) are committed, rebuilt
  deterministically by their editor builders, and listed in
  `EditorBuildSettings` as `[Game, Calibration]`.
- **Performance.** At view distance 8 with 1,445 chunk views resident, the
  headless PlayMode lane records **mean 1.178 ms / p50 1.136 ms / p95 1.576 ms
  / p99 2.020 ms** (overlay off; 1.219 / 1.162 / 1.645 / 2.004 with it on)
  against the 11.1 ms/90 Hz budget. The number is CPU-side render submission in
  the editor lane; the on-glasses RTX 5070 check is the HIL run. Method:
  [`../perf/m1.md`](../perf/m1.md).
- **Release plumbing.** `.github/workflows/release.yml` (dispatch-only) builds
  the Windows x64 player with the committed
  `Cubeglass.Editor.BuildPlayer.BuildWindows64` method and attaches it to this
  release when the `v0.1.0` tag exists. The `build_target` input picks the
  `hosted` route (GitHub-hosted runner; needs the `UNITY_LICENSE`,
  `UNITY_EMAIL` and `UNITY_PASSWORD` secrets) or the `self-hosted` route (a
  Windows runner on the Hub-activated machine; no Unity secrets).

## Known issues (deferred minors)

- `SliceBlockRegistry` duplicates the six `blocks.json` entries in code because
  Unity does not ship `System.Text.Json`; a drift test keeps them in sync.
- Each mesh upload snapshots the chunk and its 26 neighbours on the main thread
  (~213 KB transient); snapshot caching/off-thread meshing is later work.
- Boot replays a stored delta and the in-memory merged map (idempotent
  double-apply; counters count both).
- `FileWorldStore`'s publish-fallback wording suggests an unexpected
  `File.Replace` failure on the normal first-write path.
- An edit in the same frame as a world compaction can land in the
  pre-compaction world for one tick (the next tick re-resolves).
- `World.ChunkChanged` carries the chunk, not the edited cell, so remeshing
  dirties the Chebyshev-1 neighbourhood (a correctness-safe superset).
- The quit/pause flush has a bounded 2 s wait; one `FileWorldStore` per world
  is required; two stores for the same world are not mutually serialised.
- The HUD is a single monocular **left-eye** IMGUI pass in the side-by-side
  target: the right eye sees no reticle/hotbar and there is no stereo depth.
  The reticle is screen-centred, so its direction is identical in both eye
  views; per-eye HUD geometry is deferred to M2+ (ADR-0011; the S7 HIL
  checklist asks the owner to confirm left-eye readability and right-eye
  comfort).

The full list with rationale is in the S7 gate note section 12.

## Build and run (Windows x64)

Two dispatch routes build the player (**Actions → Release → Run workflow**,
`build_target`):

- **`hosted`** (default): GitHub-hosted `windows-latest`, requires the
  `UNITY_LICENSE`, `UNITY_EMAIL` and `UNITY_PASSWORD` repository secrets and
  uploads `Cubeglass-windows-x64`.
- **`self-hosted`**: a Windows runner on the machine whose Unity editor is
  activated through the Hub (this owner's Unity Personal), so no Unity secrets
  are needed; uploads `Cubeglass-v0.1.0-win-x64`. Runner setup and build
  details are in [`../ci.md`](../ci.md#release-workflow).

Unattended Unity activation accepts only a Pro/Plus/Enterprise serial, a
floating licence server or an offline `.ulf` (`unity license activate --file`);
`--personal` does not work unattended, and the `.ulf` flow is deprecated for
Hub-activated accounts, so none of them is available here:

| Option | Needs | Used here |
| --- | --- | --- |
| Editor serial (`unity license activate --serial`) | a Pro/Plus/Enterprise serial | no: the account is Unity Personal |
| Floating licence server (`unity license activate --floating`) | a reachable Unity licence server | no |
| Offline licence file (`unity license activate --file`) | an exported `.ulf` | no: deprecated for Hub-activated accounts |
| Self-hosted runner with Hub activation | the licensed Windows machine | **yes** — the `self-hosted` route |

Either route ends with the `Cubeglass` player folder; download the workflow
artefact, or build locally with Unity 6000.6.3f1:

```powershell
powershell -File scripts/sync-unity-plugins.ps1
unity run unity/Cubeglass -- -executeMethod Cubeglass.Editor.BuildPlayer.BuildWindows64
```

The player starts in `Assets/Scenes/Game.unity`; saves live under
`%USERPROFILE%\AppData\LocalLow\<company>\<product>\Cubeglass\saves\default`.
